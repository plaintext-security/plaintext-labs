# Validation — Forensics 15: Forensic Eval Harness

## Validation command

```bash
make up && make demo && make down
```

`make demo` runs `eval.py --demo`, which scores the GOOD detectors (gate GREEN,
exit 0) and then the planted REGRESSION (gate RED), ending with:

```
PASS: gate is GREEN on the good detectors and RED on the regression
```

(exit code 0). A non-zero exit, a missing PASS line, or a fail-closed `ERROR`
means the lab is broken.

## Prerequisites

- Docker + Docker Compose v2 (`docker compose`, not `docker-compose`).
- ~512 MB RAM. **No network needed** — the image installs `python3`, `python3-yaml`,
  and `yara` from the Ubuntu base, and the eval runs entirely over the committed,
  labelled corpus. Fully offline and deterministic, suitable for CI.

## What gets exercised

- `data/timestomp_corpus.json` + `data/labels.json` — the held-out file-metadata
  half (`$SI`/`$FN` modified-time pairs); benign near-misses (`ts-007` installer,
  `ts-008` backup script) are the hard cases.
- `data/pe_fixtures/` — inert PE files generated by `data/make_pe_fixtures.py`
  (MZ header + embedded strings; no code, safe to commit/run). The real `yara`
  binary scans these with `data/meridian.yar`.
- `regressed/meridian_loose.yar` + `regressed/detectors_regressed.yml` — the planted
  regression (YARA loosened to `/update.bin` alone; timestomp threshold dropped to 2 s).
- `scripts/eval.py` — `--detect` (write per-file verdicts), `--score` (scorecard),
  `--demo` (gate good→green then regressed→red). Fails closed on any unreadable
  fixture, unparseable config, missing label, or `yara` error.

## Validation status (host, no Docker)

Docker is **not available in the authoring environment**, so `make up/demo/down`
was **not** run here. The eval *logic* was validated on the host by:

1. Running the timestomp + scoring math directly against the committed corpus and
   answer key — confirmed GOOD: timestomp recall 1.0 / precision 0.667 (FPs on the
   two benign near-misses, as intended — the rule favours recall); YARA precision/
   recall 1.0. REGRESSED: YARA precision drops to 0.667 (< 0.95 floor) → gate RED.
2. Running `eval.py --demo` end-to-end against temp copies of `data/` and
   `regressed/` with a faithful `yara` stub (MZ + all declared rule strings present)
   on `PATH`. Result: exit 0, ending with
   `PASS: gate is GREEN on the good detectors and RED on the regression`.

The real `yara` binary applies the same `MZ + required strings` conditions as the
stub, so behaviour in-container matches. **Still owed before this lab counts as
